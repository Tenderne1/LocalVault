一、项目是什么
═════════════════════════════════════════════════════════════════
- 自研【本地密码管理器】LocalVault，不依赖云端存储。
- 形态：Windows 桌面端（Tauri 2 + React + Rust）+ 安卓 App（Tauri 2 Android）。
- 数据：本地 SQLite 加密库，主密钥由 Argon2id 派生。
- 同步：手机与电脑通过局域网服务 + 二维码（扫码同步）完成。
- GitHub 仓库：https://github.com/Tenderne1/LocalVault
  （公开仓库，git remote 已配置，可直接 push）

三、技术栈与核心架构
═════════════════════════════════════════════════════════════════
- 桌面/安卓：Tauri 2（WebView 前端 + Rust 后端）
- 前端：React + TypeScript + Vite
- 加密：Argon2id（ARGON_MEM_KIB=131072=128MB、ITERS=3、LANES=2）
- 存储：SQLite 加密库（cipher），保存用事务原地增量更新
- 会话机制：session_key（OsRng.fill_bytes 生成）
  ★ 关键：create()/unlock()/restore() 三处【都必须】生成 session_key，
   否则后续保存流程 session_encrypt() 会报 "Vault locked"（历史 bug，见第六节）
- 自动锁定：前端计时器（无操作 N 秒后锁定；不因鼠标/键盘活动重置）

六、v1.9.4 重要修复历史（接手必读，避免重蹈覆辙）
═════════════════════════════════════════════════════════════════
1. 【保存后强制锁定 bug】用户复现：首次建库→新建密码→保存→弹回解锁页报 Vault locked。
   根因：vault.rs create() 漏生成 session_key；保存流程 sanitize_entries()→
   session_encrypt() 在写库成功后脱敏阶段报错，前端捕获 /vault locked/i 弹回。
   修复：create() 补上与 unlock() 一致的 OsRng.fill_bytes 生成 session_key。
   （仅创建后第一次保存复现，unlock/restore 本就生成，唯独 create 漏）

2. 【手机同步无二维码按钮】创建完 rev code 点手机同步无二维码，锁定再解锁才有。
   根因：前端仅 sync.running 时渲染按钮；后端 vault_create 建库后未启动同步服务
   （只有 vault_unlock 调 sync_bridge.on_vault_unlocked）。
   修复：vault_create 也调 on_vault_unlocked（填充 + 同步服务对称启动）。

3. 【性能优化（用户拍板保持现状）】
   - 创建主密码卡顿：加 isCreating loading 提示 + 恢复码生成与 loadCategories 并行。
   - 保存约 1 秒延迟：从"整库重建文件+改名替换"重构为"SQLite 事务原地增量更新"
     （INSERT OR REPLACE entries / 删除缺失 / history 照旧）。
   - 对比 1.9.3 后结论：Argon2 参数两版完全一致（128MB/3/2），延迟来自
     SQLite synchronous=FULL 的事务提交 fsync 落盘 + H 盘（外置/机械盘）偶发写入，
     实测第 1/2/4 次提交 473/399/466ms，后续稳定 4-6ms；Argon2 派生仅 318ms。
   - 用户拍板："行，就这样吧，不改了"（保持 FULL，安全优先）。★ 不要擅自再改。

4. 【SHA256SUMS 生成 bug】release.yml 用 $_.Name（Get-FileHash 对象没有 Name 属性）
   导致前几行只有哈希缺文件名。修复：ForEach-Object { "$($_.Hash)  $(Split-Path $_.Path -Leaf)" }，
   commit 56684a8 已推送。若未来 Release 的 SHA256SUMS.txt 又出现缺文件名，
   用发布手册【7】节命令重新生成并上传覆盖。

5. 【故障日志默认关闭】发布版不预置 diagnostics-settings.json 时日志关闭；
   诊断文件写在便携版 data\LocalVault.log；计时日志事件名：
   create_argon_done/create_done/save_read_done/save_tx_done/save_done（带 now_ms + 版本）。

八、老用户兼容性硬约束（发布时绝不破坏）
═════════════════════════════════════════════════════════════════
1. 更新器公钥不可换（否则所有老用户无法自动更新）。
2. 数据库加密参数不可变（Argon2 参数、SQLite 结构、密钥派生方式）。
3. 同版本重发不触发自动更新（更新器按版本号判断）——
   重发同版本时，已装旧版的用户需手动下载，属正常现象，需在发布说明中提示。
4. 发布资产 SHA256 必须与 GitHub 一致（本地 release 从 GitHub 下载回填）。

九、已知坑点与经验（省时间）
═════════════════════════════════════════════════════════════════
1. PowerShell 5.1 把 git 的 stderr 当错误 → 推送成功也会报红色 exit=1（误报，属正常）。
2. curl.exe 上传 GitHub 资产会 SSL schannel 失败（curl:35）→
   一律用 PowerShell Invoke-RestMethod -Method Post -InFile 上传。
3. 本机未安装 gh CLI；Bash 工具不可用（Windows 主机用 PowerShell）。
4. 中文文本文件保存用 UTF-8 BOM（记事本才不会乱码）——用户对此非常敏感。
5. 用户明确要求过：不要在物理桌面操作（若涉及虚拟机/虚拟桌面，一切操作在虚拟桌面内）。
6. 用户偏好精简直接的回答、表格对比、明确结论，讨厌"AI 味"和空话。
